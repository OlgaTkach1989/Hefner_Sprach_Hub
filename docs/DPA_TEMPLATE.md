# DPA Template

This is a working template for a Data Processing Addendum for `Learning Hub`. It is a product template and must be reviewed by legal counsel before signature.

## 1. Parties

This Data Processing Addendum is entered into by:

- `Controller`: the customer organization using `Learning Hub`
- `Processor`: the operator or vendor of `Learning Hub`

## 2. Subject matter

The Processor provides an enterprise learning platform used for:

- internal learning delivery
- onboarding
- course administration
- cohort scheduling
- completion evidence and attestation
- operational reporting

## 3. Duration

This DPA applies for the duration of the master agreement and until customer personal data has been returned or deleted in accordance with the agreed retention and exit terms.

## 4. Nature and purpose of processing

Processing activities may include:

- user account creation and authentication
- course enrollment and access control
- learner progress tracking
- session attendance tracking
- completion evidence generation
- support and operational diagnostics

## 5. Categories of data subjects

- employees
- contractors
- trainers and instructors
- platform administrators
- invited external learners where applicable

## 6. Categories of personal data

- name
- email address
- role and access metadata
- cohort and enrollment data
- attendance data
- lesson progress data
- attestation data
- audit metadata related to platform operations

## 7. Processor obligations

The Processor shall:

- process data only on documented instructions
- ensure personnel confidentiality
- implement appropriate technical and organizational measures
- support the Controller with data subject requests where applicable
- notify the Controller of personal data breaches without undue delay
- support audits and security questionnaires on a reasonable basis

## 8. Security measures

Security measures should include, as applicable:

- authenticated access to administrative surfaces
- TLS for internet-facing traffic
- database and media backups
- role and scope-based access control
- audit logging for governance actions
- restore procedures and operational runbooks

Reference package:

- [SECURITY_PACKAGE.md](SECURITY_PACKAGE.md)

## 9. Subprocessors

Approved subprocessors shall be listed in:

- [SUBPROCESSORS.md](SUBPROCESSORS.md)

## 10. International transfers

International transfer terms must be defined per deployment and subprocessor profile. If cross-border transfers apply, the parties should attach the appropriate safeguards and transfer mechanism.

## 11. Deletion or return of data

Upon termination, the Processor shall, at the Controller's option and subject to legal obligations:

- return customer data in an agreed exportable format
- delete customer data from active processing systems
- retain only data required by law, security, or explicit contractual retention terms

## 12. Audit and assistance

The Processor shall:

- provide reasonable responses to customer security questionnaires
- support evidence requests about backups, logging, and access controls
- allow audits or alternative review mechanisms subject to notice, confidentiality, and operational safeguards

Complete the following before signature:

- customer legal entity name

- deployment region
- retention schedule
- subprocessor list
- incident notification contact
- security contact
- deletion and offboarding workflow
